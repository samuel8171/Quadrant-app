## 两条值得记住的量测结论

1. **headless 里 rAF 轮询会把时序量坏。** `page.waitForFunction` 默认 `polling: 'raf'`，
   headless 下 rAF 被压到 ~1Hz，于是「卡片在 3.27s 离开」被量成 4.24s。
   加 `polling: 25` 后数值立刻回到 3274ms（= 3000ms 保持窗口 + 200ms 移出过渡）。
   ⇒ 凡是量"多久之后发生"的探针，**都必须显式指定定时器轮询**。
2. **手机档面板默认收起，`innerText` 对 `visibility: hidden` 的元素返回空串。**
   顺序断言必须用 `textContent`（`allTextContents()`），否则会把"看不到"误读成"没有内容"
   —— 第一次跑就踩了这一条。

## 实现要点（为什么这么做）

- **历史 = `goal.done`，不新增字段。** 需求里「取消勾选回主页」正是 `done → false`，
  与现有唯一布尔位一一对应；新增 `archived` 要同步网页校验 / 桌面 codec / 类型三处，
  漏一处静默丢字段。
- **3 秒保持是纯展示层窗口**：`toggleGoal` 在点下那一刻就落库，窗口只决定卡片何时
  从主页摘除（先 `.is-leaving` 播 `grid-template-rows: 1fr → 0fr` 折叠动画，再由
  `transitionend` + 兜底定时器摘除）。因此刷新/切页不会让状态分叉。
- **预设顺序用 `weekPresets` 的数组顺序**，不给 `WeekPreset` 加 `order`：数组顺序本来就
  已持久化（`addPreset` 一直尾部追加），而加字段要同步三处并给旧数据做迁移赋值。
  `reorderPresetsInList` 对未提及的 id 一律补到尾部（丢预设不可逆）。
- **拖动用的不是「只画插入位指示线」那套了**（2026-10-09 二次改造）：现在拖动期间**按草稿顺序
  渲染**，让位动画交给 `@formkit/auto-animate`（WAAPI + `MutationObserver(childList)`）；
  被拖的卡片 `visibility: hidden` 留在原位当"空位"，跟手的是一个 portal 到 `document.body`
  的**幽灵副本**。为什么必须拆成两半：库的 WAAPI 动画在层叠里高于内联样式，会盖掉跟手的
  `transform`。完整推导与实测见 `docs/research/2026-10-09-preset-reorder-animation.md`。
- **轴向由 `getComputedStyle(list).flexDirection` 决定**（桌面纵向 / 手机抽屉横向），
  落点判定下沉到纯函数 `resolveDropIndex`（可单测，已覆盖 ±1 格这类边界）；
  指针事件挂 **window** 而非 `setPointerCapture`（被拖卡片隐身/被移位时捕获不可靠），
  `touch-action: none` 仍写在拖柄上（按下即锁存，整段手势不退化）。
- **完成即离场必须同时解除周计划镜像链接**：`WeekEvent.quadrantEventId` 悬空时，
  用户下次编辑那条周事件会被 `updateWeekEvent` 的 else 分支**重新造一张卡片**出来。
  同一 helper 也修了 `deleteEvent` / `cutEvent` 的同类隐患。卡片上的照片实体一并回收。

# 第二轮（2026-10-10）：同步数据丢失 + 手机全屏排序 + 滚动落点 + 日结栏空隙

用户报四条：① `npm run dev:web` 会**覆盖云端**（数据丢失）② 手机端排序要全屏 + 放大动画
③ 桌面端拖动时滚动列表后落不进新出现的槽位 ④ 手机端日结卡片与下方文字空隙过大。
本轮探针从 43 条涨到 **65 条断言，全绿**；单测 457 → **465/465**。

## ① 云端被覆盖（恶性，优先）

**根因（三条叠在一起，缺一条都不会丢）**：

1. `appStore.init()` 里**对账排在本地维护之后**：`materializeLedgerDays()` 等会 `saveSoon`
   ⇒ 触发自动上传，而此时**还不知道云端有什么**。
2. `syncAfterLocalSave` 在任何本地保存后都直接上传，没有"首次对账完成了吗"这个概念。
3. `decideStartup` 把 `meta.dirty` 当作"离线编辑优先"，但 `dirty` **不区分**
   「同一台设备的离线编辑」与「本机从来就是另一份东西」。
   `localStorage` 按 **origin** 隔离 ⇒ `npm run dev:web` 的 `localhost:5173` 在同步层
   是一台**新设备**，口袋里还装着开发期残留的旧数据。

合起来：打开 dev 网页 → 本地维护触发一次保存 → 陈旧数据整份推上云端。**用户什么都没点。**

**修法（四处，都在同步层）**：

| 改动 | 位置 |
| --- | --- |
| 首屏对账出结论前**一律不自动上传**（只记 `dirty`） | `appStore.ts` 的 `reconciled` 闸门 |
| `init()` 改为**先对账、再本地维护** | `appStore.init` |
| ⭐ `decideStartup` 新增「本机从未对过账 ⇒ 采纳云端」；**删掉 `dirty` 优先那条** | `syncMeta.ts` |
| 采纳云端前把本机那份**另存快照**（`quadrant-web-data-conflict-snapshot`） | `appStore.stashConflictSnapshot` |

新规则一句话：**谁的修订号新谁说了算；修订号一致 = 已同步；本机没有记忆 = 新设备，听云端的。**

⚠️ 明确的取舍：两边都改过时**云端胜出**（用户要求云端不能被顶掉）。被顶掉的本地那份
会留快照，不会无声消失。

## ② 手机端排序改全屏面板

`.preset-sort-sheet`（`position: fixed; inset: 0`，z-index 210，幽灵卡片 220）：
打开播 220ms `scale .9 → 1` + 淡入，关闭 160ms 缩小淡出（`useClosing` 驱动）。
面板里的列表**回到纵向**（覆盖抽屉那条 `flex-direction: row` + 横向吸附），
卡片高度回到与桌面端同一个公式 ⇒ 交互逻辑与桌面端完全一致。
退出排序时**不再收起抽屉**（改 `prevMobileRef` 只在断点真的变了时才重置展开态）。

## ③ 拖动期间滚动列表后落不进新槽位

**根因**：落点判定用的是**视口坐标**，而视口坐标会随 `scrollTop` 整片平移 ——
滚动之后按下时记下的那批槽位坐标全部作废。另外「指针不动、只滚列表」时
一个 `pointermove` 都不会发，落点根本不会重算。

**修法**：几何一律换算到**列表内容坐标系**（`内容 = 视口 − 列表矩形 + 滚动量`，
见 `PresetPanel.listOrigin`），并新增列表 `scroll` 事件监听复用同一个
`recomputeIndex`。

**另发现并修掉一个可见跳动**：拖动期间我们自己重排 DOM，而 Chrome 的**滚动锚定**
会同时去调 `scrollTop`。实测（矮视口 + 滚到底 + 跨中线重排一次）：

| `overflow-anchor` | 重排前 | 重排后 | 位移 |
| --- | ---: | ---: | ---: |
| `auto`（默认） | 195 | 105 | **−90px** |
| `none` | 195 | 195 | **0px** |

⇒ `.preset-list` 上加 `overflow-anchor: none`。

## ④ 手机端日结卡片与下方文字空隙过大

**根因**：**安全区被避让了两次**。`.settle-card` 的 `margin-top` 已经是
`calc(24px + var(--safe-top))`（安全区在卡片上面消化掉了），而它下面的
`.weekly-page` / `.day-page` 又各自带 `calc(24px + var(--safe-top))`。
叠加 = `24 + 24 + safe-top`，safe-top 取真机常见的 47 时就是 **95px** 的空档。

**修法**：`.settle-card + .weekly-page, .settle-card + .day-page { padding-top: 0 }`
（相邻兄弟；`SettleCard` 在 `count <= 0` 时返回 `null`，此时选择器不命中，
页面照常自己避让）。页面的左右内边距不动。
回归：`scripts/statusbar-clearance-probe.mjs` 仍 **✓ 全部目标的状态条余量达标**。

# 第三轮（2026-10-10）：全屏排序面板的标题被压扁 + 箭头未居中

用户报：`调整顺序` 全屏面板里「事件名称显示」不对、右侧上下移箭头位置不对（应**居中事件块**）。
探针 65 → **69 条断言全绿**；单测 465/465。

## 两个缺陷根因不同，但都长在"抽屉的规则漏进了全屏面板"上

### ① 标题被压成 0 高（不是没渲染，是渲染了看不见）

**实测**（手机 390×844，7 张预设）：

| 预设 | 卡片高（内联） | 标题盒高 | 现象 |
| --- | ---: | ---: | --- |
| 20 分钟 | 64 | **0** | 整张卡只剩「20分钟」 |
| 30 分钟 | 68 | **0** | 只剩「30分钟」 |
| 1 小时 | 80 | **0** | 只剩象限行 + 时长 |
| 2.5 小时 | 116 | **8** | 标题被压到 8px ⇒ 与下一行糊成重影 |

链条：卡片高度是**内联写死的**（随预设时长伸缩：`56 + 小时数 × 24`），而内容要
`19(标题) + 15(象限行) + 15(时长) + 行距 8 + 内边距 20 = 77px`。
flex 列里装不下就按 `flex-shrink` 压缩 —— 正常情况下 `min-height: auto` 会兜住，
但 **`.preset-title` 带 `overflow: hidden`**，按 Flexbox 规范这类元素的"自动最小尺寸"
**退化为 0**，于是它成了唯一能被压到 0 的子项，把差额全吃了。

⭐ 为什么桌面端同一条公式却没事：桌面**没有 meta 时内容只有 36px**（<45 分钟不显示
象限行），而 ≥45 分钟时卡片已有 60px 以上；真正把内容顶爆的是抽屉那条
`.preset-actions { position: static }` —— 44px 的按钮组混进了纵向流（这也是缺陷 ②）。
所以这是**全屏面板专属**的缺陷，桌面侧栏实测标题恒为 17px。

**修法**：全屏面板里给文字栈 `flex: none`（不参与收缩）+ 卡片 `min-height: 78px`
（77 + 1px 余量）+ 内容 `justify-content: center`。

### ② 箭头落在卡片下沿、还被裁掉一截

抽屉里卡片是 136px 宽的横排窄条，放不下浮动按钮，于是
`.preset-actions { position: static; display: flex; justify-content: flex-end }`。
这条规则**同时命中了全屏面板**（同一个 media query 内的单类选择器），
按钮组于是混进卡片的纵向流、顶到卡片下沿（实测 `top=53` + 高 44 = 97 > 卡高 80，
下面 17px 被 `overflow: hidden` 裁掉）。

**修法**：`.preset-sort-list .preset-card .preset-actions` 按回 `absolute`，
`top: 50% / translateY(-50%)` **垂直居中**，并给卡片 `padding-right: 106px`
（2×44 按钮 + 间隙 2 + 右偏移 10 + 余量 6）当通道，标题的省略号在通道之前就结束。

### ③ 顺带：幽灵卡片要跟着换排布

面板里的本体换成了"内容居中 + 右侧按钮通道"，而幽灵是**副本**、且挂在 `document.body`
上（没有 `.preset-sort-list` 祖先）。不跟着换的话，起拖那一刻文字会跳一下。
故幽灵多认一个 `sheet` 类（只在全屏面板里加，桌面侧栏不加），
`.preset-card.preset-drag-ghost.sheet` 补上同一组几何。

## 本轮新增的 4 条断言

  [ok] 上下移按钮在卡片里垂直居中 — 偏差 0px（absolute） / 偏差 0px（absolute）
