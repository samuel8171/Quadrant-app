# 象限前端审视与改版提案

2026-11-18 · 主分支 `695abce` · 应用版本 1.4.2 · 讨论稿

这次改版围绕三个时刻展开。进「我的」能读懂本周的时间账，进四象限能顺手摆卡、成组和找回远处的内容，写周日复盘能一直看见正在写的那一行。Dashboard 沿用现有「我的」整页。

## 实测基线

使用项目开发探测页挂载真实组件，在隔离的无头 Edge 中分别测试 1280 × 800 桌面和 375 × 667 触屏视口。仪表盘覆盖金钱系统关闭、开启但无记录、带三条合成记录三种状态。桌面端使用鼠标与键盘，触屏使用实际的 Chromium 触摸事件。iOS 独立模式与中文软键盘仍需真机验收。

| 动作 | 现在发生的事 | 对设计的影响 |
| --- | --- | --- |
| 在复盘长文末尾换行、输入 | 输入到 84 行时，桌面外层滚动位置从 1768 px 跳回 0。对照实验仅跳过把活跃文本框高度设为 `auto` 的一步，同一段输入留在末尾 | 测量文字高度要独立于正在接收输入的控件 |
| 复盘记录 → 返回 | 桌面保留了 2162 个字符，文本框可见高度仅 81 px，内容需要 2245 px，外层可滚动距离为 0 | 返回写作视图时需要重测，恢复阅读位置 |
| 鼠标拖一张 120 px 宽的卡跨轴 | 鼠标移动 2 px，卡片的横坐标从 10 跳到 −130 px。拖卡面只选中，12 × 12 px 的把手才启动桌面拖动。触屏实测可整卡拖动 | 跟手位置与最终合法落点应分别绘制 |
| 两张卡相距上下 200 格，缩到最小 | 桌面滚轮约 50%，手机双指 50%，两端依然超屏。桌面与手机横向平移都在原点距边界 10 px 处停止 | 可用世界范围、平移边界、全览比例需要一起改 |
| 打开「我的」 | 桌面第一排两个 492 px 宽的面板，第二排四个 240 × 175 px 面板。手机「娱币趋势」从页面 y=677 开始，「执行质量」从 y=1030 开始 | 同一套卡片外壳把次要信息放得很大，真正要比较的数据却很小 |

## Dashboard 的方向

产品服务于按周安排时间的学生。建议沿用深色底、中文系统字体和蓝色选中态，把「我的」排成一页可读的周账。界面给人的感觉是安静、有刻度、用数字说话。最亮的两处分别留给当天的时币数据和四象限正在接收卡片的目标。周计划、周趋势和复盘日期共用一枚短刻线标出读到哪一天。

| 区块 | 看见的问题 | 建议的具体改法 |
| --- | --- | --- |
| 双币余额 | 本周额度、余额、已用额度散在标题、数字和进度条三处 | 做成账页页首，左侧大字读时币余额，右侧读娱币余额，各自紧跟单位。周起止日期和已用／额度各出现一次。数字用等宽数码，零、负数、小数均能对齐 |
| 惩罚预告 | 正常周也用大绿色圆章写 0，下方又写一次「档位 0 · 无惩罚」 | 保留「按目前记录预计」的含义。正常时用一行交代下周额度，有影响时展开时币、娱币各自的变化和预计额度。警示色只标发生变化的数值 |
| 时币趋势 | 曲线与额度虚线被压进小卡，读者难以从图上读出某日花了多少 | 升为整页主图，桌面约占趋势区域三分之二。保留日额度参考线并直接标数。点按或键盘选择一天，读出当日消耗。为当天与超额点保留强调色 |
| 娱币趋势 | 外观与时币曲线相似，实际含义是有正负的每日净变化 | 与时币对齐周一到周日的刻度，用独立零轴画正负细柱。标题给出本周净变化。同一日期可以在两图对读，纵轴各用自己的单位与范围 |
| 深夜时段 | 在很长的槽条与两行说明之间才能读到分钟数 | 收成一行「深夜做事 X 分钟 · 占实际做事时间 Y%」。零记录时给出没有记录的状态，保留真实记录中 0 分钟的含义 |
| 执行质量 | 四种颜色、四个零和空槽在无记录时占满一卡 | 有记录时保留四段条，旁边把类别和条数对齐。标明可判定条目数。分母为零时呈现一行简洁空态 |
| 设置、关于、导航 | 「云同步状态」一行实际描述同步方式。侧栏口号、发光的当前项和标题旁蓝线都在争注意力 | 设置保留清晰的开关和外观入口，「关于」改用准确标签「同步方式」。侧栏淡化选中底色，保留键盘焦点环。留出原口号占据的空间。关闭金钱系统时沿用用户的选择 |

例如在本次合成账本中，页首可以直接读成「本周还剩 418 时币、17.5 娱币」，下一行是「按当前记录，下周额度照常」。这些数值都来自现有账本。适配时沿用现有中文字体，数字建议 28–32 px、正文 14–16 px，手机可点行至少 44 px。

桌面按「本周余额和预计结果 → 主图与副图 → 两项执行摘要 → 设置、关于」阅读。手机同序，以短屏首屏能读到余额、下周预计结果和主趋势为排版目标。图表对有记录的零值、缺席日期、未来日期分别绘制。当前选择器的七项数据会把缺席日补零，绘图时要从现有账日判断记录状态。现有蓝、粉系列色可以沿用，荧光集中在选中的日期。

实现时可在现有组件内精修，由六张独立卡保持各自的边界。也可以把六项内容组织为一页周账，减少重复边框并建立图表主次。前者改动较小，手机上仍需经过多张卡。建议采用后者，继续由现有选择器计算各项数值。[仪表盘页面](../../src/renderer/src/pages/MinePage.tsx) · [统计口径](../../src/shared/money.ts)

## 把四象限变成可用的大画布

1. **扩大实际摆放范围。** 建议起始工作区 240 × 200 世界格，相当于 100% 时的 4800 × 4000 逻辑像素，各设备共用这个尺度。靠近边界继续拖动时向对应方向扩展，已有远端卡或卡组也纳入边界。已有卡继续使用已有世界坐标。扩展后的边界随布局保存，松手时统一提交。各设备分别记住适合自己屏幕的视野。Canvas 只绘制当前视口，扩展工作区无需分配一张巨型位图。
2. **增加「全览」与「返回刚才位置」。** 平移允许坐标原点离开视口。全览按实际可用矩形、画布上下边界和卡面外缘计算比例，扣除标题、底栏、安全区和边距。先保证纵向两端同时可见，两端横向相距较大时再按宽度缩小。最小缩放比例随需要降低。全览后可定位某卡继续编辑，也可回到进入全览前的中心与倍率。
3. **把拖动与落位拆开。** 桌面按住卡面越过现有位移阈值即可拖，照片、按钮和文字编辑区有独立命中范围。触屏沿用整卡拖动、空白单指平移、双指缩放。拖动层保留手指抓住的那个点，细轮廓预告最终落位。普通移动在松手时提交，跨象限入组在弹窗确认后提交。Esc、指针取消或双指接管均取消拖动预览。
4. **让人认得方位。** 保留右上重要紧急、左上重要不紧急、左下不重要不紧急、右下不重要紧急的现有语义。标签随可用空间显示，低倍率仍有文字与方位提示。四种颜色用于标签和落点。降低大片底色、亮边的对比度。用可点的「添加」和「全览」入口替代让新用户记住所有手势的提示胶囊，双击新建继续可用。

初始世界尺寸是提议值。全览按你给的「上下两端都看得到」来算。纵向取完整工作区的上下界，并包含边缘卡面的实际高度。横向取要同时显示的卡片与卡组的左右外缘，空白横向区域仍可平移。实际可用视口宽高记为 W、H，需要容纳的宽高换算成 100% 逻辑像素后为 w、h。四周留白 p 时，全览倍率取 `min((W−2p)/w, (H−2p)/h)`，空画布按初始工作区高居中。顶栏和底栏可能不对称，中心对准实际可用矩形。低倍率下优先显示选中卡标题和组名，点卡可以回到可读倍率。拖到边缘扩展时，指针下的世界坐标保持稳定。[画布页面](../../src/renderer/src/pages/QuadrantPage.tsx) · [坐标与缩放](../../src/renderer/src/lib/quadrantMath.ts)

## 四象限页的视图切换

在四象限页提供「画布 / 列表」切换。列表视图用四张大卡片分别承载「重要紧急」「重要不紧急」「不重要紧急」「不重要不紧急」的事件。两个视图共用同一批事件和卡组，在任一视图里拖动卡片、拖叠成组、加入已有组或展开卡组，都遵循相同的操作规则。切回另一视图时，卡片所属象限与组内成员同步反映刚才的操作。

## 卡组与跨象限关系

- **形成和追加。** 卡片已经开始拖动后，指针进入目标卡中央并停稳约 400 ms，目标露出第二层卡边。同象限显示「松手成组」或「松手加入」，松手即完成。跨象限松手后按下方规则确认。继续掠过、移出中心或取消都不改变组籍。400 ms 是试调起点，桌面和触屏分别验误触。
- **代表卡与弹窗。** 同一组在同一象限的成员默认堆叠，展示标题、当地成员数，并可查看全组数。点主堆展开卡组弹窗，按象限列出原卡、截止时间与已有操作。提供定位、移出组和键盘可达的加入入口。照片、备忘、计费仍属于各自事件。建议默认取目标卡标题作组名，允许改名。
- **跨象限连接。** 远端卡或当地子堆挂一个带组名的方向页签，例如「↖ 准备答辩」。选中、键盘聚焦或点按页签时，只显示这一组的细连接线，位于卡片下方。主组在屏外时页签可定位，随后可返回刚才位置。组籍由文字和线端共同传达，四象限的颜色继续表达重要性和紧急性。
- **整组与单卡。** 拖整个主组跨轴，所有成员一起改变象限。只移动某张卡或该卡到时自动升级，只更新这张卡的象限，保留组籍，在目标象限与同组成员堆叠。已结算账目沿用历史快照。
- **跨象限拖卡入组。** 卡片与目标卡或卡组所在象限不同时，停稳松手后弹窗询问是否同时改变该卡的象限。弹窗写明原象限和目标象限，例如「加入『准备答辩』时，要把『今天要交』从『重要紧急』移到『重要不紧急』吗？」选「保留原象限并加入」，卡片成为远端成员；选「移到目标象限并加入」，卡片在目标象限堆叠。取消则撤销本次拖放。画布与列表均在用户选择后一次提交。
- **数据与恢复。** 事件保留原 ID、象限、坐标，额外引用稳定的组 ID。组记录保存名称和主锚点。主象限暂时没有成员时，只要其他象限还有成员，主锚点就保留带组名的定位标记。整组拖动一次提交，从真实事件推导成员数和连接。周计划自动放入象限时的容量继续按实际事件计数。旧数据缺少新字段时按原来的散卡读取，联测桌面读写、网页校验和模拟云端往返。
- **保护周计划关联和账本。** 同一周计划事件改象限时，优先用已有 `quadrantEventId` 更新原卡的位置和象限，延续组籍、备注、照片和来源关联。若确需换 ID，在同一数据变更中迁移成员关系、照片引用和周计划指针。找不到有效前身时按新散卡处理，避免同名卡被误入组。历史账目的标题、象限、时长、费用均读取既有条目快照，后续移卡、分组与改名只影响当前画布及后续新记账。历史条目无需记录组名、坐标或连接线。[周计划与象限联动](../../src/renderer/src/state/appStore.ts) · [账本条目字段](../../src/shared/types.ts)

## 复盘与公共动效

**复盘先修两条路径。** 桌面维持长文随内容展开、外页滚动的写作方式。用独立的等宽测量元素计算换行高度，宽度、内边距和字体与正文一致，只在高度实际变化时更新。文本框重新挂载、宽度变化、已有草稿恢复时都重新测量。进入记录前记住选区和滚动位置，返回时恢复。手机让固定可见编辑区承担正文滚动，统一软键盘与底栏的可用高度。保存操作按平台写清结果，桌面「保存为 Word」，网页「保存记录」，「保存草稿」保留会话内草稿的现有含义。[复盘组件](../../src/renderer/src/pages/ReviewPage.tsx) · [移动端样式](../../src/renderer/src/styles/theme.css)

| 场景 | 动效覆盖 |
| --- | --- |
| 目标、预设、卡组弹窗内的普通列表 | 沿用已有 AutoAnimate 与 200 ms 共享参数。成员增减时让邻项自然补位 |
| 四象限拖动、周计划日视图拖动 | 拖动帧跟随指针。仅松手落位、组层收合使用短过渡，建议沿用 180 ms 的落位时长 |
| 仪表盘与复盘 | 给数据变化与视图切换可辨认的反馈。输入、选区和滚动位置的变化直接生效。状态文案出现时预留空间 |
| 公用弹窗、菜单与减弱动态 | 复用现有玻璃弹窗，浮层挂在画布变换层之外。开组时把焦点送入弹窗，关闭后送回触发卡。系统启用减弱动态时，JS 执行的缩放补间、松手惯性也要响应，保留选中态与可操作提示 |

当前 AutoAnimate 的实际接入在目标页与预设面板。补齐动画时用已有曲线和时长，触摸手势继续由现有状态机处理。[共享动效](../../src/renderer/src/lib/motion.ts) · [手势状态机](../../src/renderer/src/lib/gestureMachine.ts)

## 交付顺序与验收

| 批次 | 验收动作 |
| --- | --- |
| 1 · 复盘 | 桌面与手机输入、粘贴 2000 字以上，在末尾连续换行，然后删回短文。光标与末行能看到，桌面页不会跳回顶端。从记录返回后仍在原段落。补测中文输入法组合输入、软键盘开合及有周账摘要的页面 |
| 2 · 大画布与拖动 | 在 100% 能把卡放到扩展区域，在工作区上下端各放一张，令两张卡水平错开。桌面、375 px 与 390 px 手机执行全览后，两卡外缘均在可用矩形内。回到编辑倍率时位置正确。缓慢跨轴时卡片跟手 |
| 3 · 卡组与列表视图 | 同象限停稳松手成组，第三张可加入，点开可找到每张卡。跨象限验证保留原象限、移到目标象限、取消三种结果。分别在画布和列表操作后切换视图，核对象限和组籍。覆盖快速掠过、整组移动、单卡自动升级、再次打开应用与数据同步。一笔已确认的操作只提交一次 |
| 4 · Dashboard 与公共动效 | 用关闭、空账、有记录、超支、含负娱币的状态逐块复核。两张趋势的真实口径可读，正常周的预告不会淹没主图。手机和键盘能读到相同数值。减弱动态模式可完成全部操作 |

## 版本兼容

这批前端改动基于包含快照恢复的 `4d98143`。没有卡组字段的旧快照可以直接打开。包含卡组的快照由新版桌面、网页和云端共用同一验证口径。基于 `695abce` 的旧版 1.4.2 桌面端只读取当时已知的字段，重新保存时可能丢掉卡组与画布边界。上线时先统一更新会编辑同一套数据的客户端，再开始跨端使用卡组。
