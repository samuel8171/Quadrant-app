# 移动端「可操作面积」扩容方案

- 日期：2026-09-17
- 状态：**P0–P3 已全部落地并通过验收**，执行记录见第七节（周视图两项按决定不做）
- 前提：**屏幕尺寸不变**（不引入更大的设备、不做横屏、不依赖手势外的系统能力）
- 实测工具：`scripts/mobile-density-probe.mjs`（真实 Edge + 390/375/430 三种手机视口，数据播种 0/12 条预设）
- 实测原始数据：`docs/probes/mobile-density.md`

---

## 一、结论

在屏幕不变的条件下，"可操作范围变大"只有三条路：**把被非交互元素吃掉的像素还给交互区**、**把纵向堆叠改成覆盖式/横向**、**减少每次操作需要的滚动与回看**。

按「收益 ÷ 代价」排序，本方案分四批：

| 批次 | 内容 | 375×667 上的直接收益 | 代价 |
| --- | --- | --- | --- |
| **P0 缺陷** | 预设面板折叠按钮完全失效（跨端） | 折叠恢复可用：时间轴 135 → 395px | 1 行 CSS |
| **P1 结构** | 日视图预设改「底部抽屉 + 横向预设条」；目标卡 4 个图标收进「…」菜单 | 时间轴 135 → 528px（+291%）；目标标题可用宽 25 → 221px | 各动 1 个组件，不动数据层 |
| **P2 全局** | 底部导航 78→58px、页面内边距与页头压缩 | 全页面内容区 +45px（四象限画布 500 → 545px） | 视觉层级略降 |
| **P3 打磨** | 四象限页头悬浮、复盘页头压缩 | 画布再 +49px；文本框 +29px | 低 |

**最要紧的两条**：P0 是**已确认的功能缺陷**（不是设计取舍），P1 的第一项把用户点名的"预设多时时间轴很小"从根上解决。

### 2.2 已确认的缺陷：预设面板折叠按钮完全无效

探针在三种手机视口与桌面 1440×900 上给出完全一致的结论：

| 检查项 | 结果 |
| --- | --- |
| 点击后 `.preset-panel` 是否带上 `collapsed` | 是 |
| `.preset-list` 是否写上 `hidden` 属性 | 是 |
| `.preset-list` 的实际 `display` | **仍是 `flex`** |
| 时间轴高度（点击前 → 点击后） | 135 → 135px（桌面 801 → 801px） |

根因：`theme.css:1407` 的 `.preset-list { display: flex; flex-direction: column }` 是**作者样式**，它的优先级高于浏览器 UA 样式表里 `[hidden] { display: none }`。所以 `hidden` 属性写了等于没写，元素继续参与布局。

这解释了用户报告的"预设多时时间轴非常小"——**不是没救，是救生按钮本身坏了**。修复后（探针实测，强制移除列表）：

| 视口 | 时间轴可视高 | 可见小时数 | 提升 |
| --- | --- | --- | --- |
| 375×667 | 135 → **395px** | 2.8 → 8.2 小时 | +193% |
| 390×844 | 312 → **572px** | 6.5 → 11.9 小时 | +83% |
| 430×932 | 404 → **664px** | 8.4 → 13.8 小时 | +64% |

### 2.3 已确认的缺陷：窄屏上目标标题被挤成竖排

375×667 实测目标卡内部：卡片宽 317px，其中 4 个图标按钮各占 44px + 勾选框 44px = 220px 的固定支出，`flex: 1` 的标题只剩 **25px 宽**、被压成 **95px 高**（每行一两个字竖着排）。

| 视口 | 卡片宽 | 标题实际宽×高 | 图标按钮数×宽 |
| --- | --- | --- | --- |
| 375×667 | 317px | **25 × 95** | 4 × 44px |
| 430×932 | 372px | 80 × 19 | 4 × 44px |

## 三、逐模块方案

### 3.1 全局骨架（导航 + 页面框）

| 编号 | 改动 | 内容 | 收益 |
| --- | --- | --- | --- |
| G1 | 底部导航瘦身 | `.sidebar` 高 78 → 58px；`.nav-item` 由 62 高收到 46（图标 20 + 文字 10 + 上下 8px padding），仍 ≥44px 触摸下限 | 每页 +20px |
| G2 | 页面内边距 | `padding: 18px 14px calc(24px + nav + safe)` → `12px 12px calc(16px + nav + safe)` | +14px |
| G3 | 页头压缩 | `.page-header` margin-bottom 16 → 10；移动端 `h1` 23 → 19px | +11px |

合计 375×667 上内容区 485 → ~530px（**+9%**），四象限画布 500 → 545px。全部改在 `@media (max-width: 767px)` 内，桌面端零影响。

### 3.2 周计划 · 日视图（收益最大，用户点名的问题）

| 编号 | 改动 | 内容 |
| --- | --- | --- |
| W2 | **修折叠**（P0） | `theme.css` 增加 `.preset-list[hidden] { display: none }`。一行，跨端修复 |
| W1 | 预设面板改**底部抽屉** | 移动端 `.preset-panel` 脱离 `.day-body` 的纵向流，改 `position: fixed` 贴底：默认只露 44px 把手（"事件预设"＋展开箭头），展开高度 `min(240px, 40dvh)`，半透明＋模糊，**覆盖**在时间轴之上而不挤压它 |
| W3 | 抽屉内预设改**横向条** | `.preset-list` 移动端 `flex-direction: row; overflow-x: auto`；`.preset-card` 固定 `flex: 0 0 104px; height: 64px`，一行容纳约 3.5 张，取代 260px 的纵向列表 |
| W4 | 周视图**整周适配**（可选） | 新增"适配宽度"开关：列宽 = (可视宽 − 52) ÷ 7 ≈ 42–50px，事件块只显示色条 + 首字；点击列头照旧进日视图 |

收益（探针实测面板整体让位后）：

| 视口 | 时间轴可视高 | 可见小时数 | 可操作面积 |
| --- | --- | --- | --- |
| 375×667 | 135 → **483px**（叠加 G 后约 528px） | 2.8 → **10.1 小时** | 39,555 → 141,519 px²（**+258%**） |
| 390×844 | 312 → 660px | 6.5 → 13.8 小时 | +65% |
| 430×932 | 404 → 752px | 8.4 → 15.7 小时 | +54% |

代价与风险：
- 抽屉展开时会盖住时间轴下半部，属于"用时间换空间"的主动选择，符合移动端惯例（同 `.modal`、`.context-menu` 已经采用的模式）。
- 移动端拖拽落点预览（HTML5 DnD）在抽屉覆盖下不可用——但移动端本来就是"单击预设即用"（`shouldUsePresetOnTap` 已实现），拖拽是桌面端能力，桌面端布局不动。
- 不引入虚拟滚动（单用户预设量级在几十条以内，收益不抵复杂度）。

### 3.3 周计划 · 周视图

实测单列 95px × 7 列 = 665px，而可视宽只有 345–400px，**单屏永远看不到完整一周**，必须横向滚动。

| 编号 | 改动 | 收益 | 代价 |
| --- | --- | --- | --- |
| W4 | 整周适配开关（见上） | 单屏 4 天 → **7 天** | 格子内文字退化，需"点进去看" |
| W5 | 列宽默认 96 → 84px | 单屏 4.1 → 4.8 天 | 每个事件块少显示 1–2 个字 |

建议做 W4 而非 W5：W5 是折中，收益有限还损失信息密度；W4 是二值的模式切换，用户可按当周事件的疏密自行选择。

### 3.4 目标

| 编号 | 改动 | 内容 |
| --- | --- | --- |
| T1 | 卡片操作**溢出菜单**（P1） | 移动端只保留两个 44px 控件：勾选框 + 「…」；详细信息 / 编辑 / 展开子目标 / 删除 收进已有的 `ContextMenu`（组件已存在，无新依赖） |
| T2 | 保留主路径 | "展开子目标"若为长目标的主操作，可留在卡片右侧作为箭头（3 个控件：勾选 + 标题 + 展开），把详情/编辑/删除放进菜单 |

收益：标题可用宽 25 → 221px（**+784%**）；单卡高 109 → 56–64px；单屏可见 2 → 4–5 张。
代价：多一次点击才能到编辑/删除。桌面端不改（有足够宽度）。

### 3.5 复盘

| 编号 | 改动 | 内容 | 收益 |
| --- | --- | --- | --- |
| R1 | 页头压缩 | 三个按钮改「图标 + 2 字」等宽三列，高 44px；页头 85 → 56px | +29px 给文本框 |
| R3 | 去掉脆弱的硬编码 | `theme.css:2429` 的 `max-height: max(96px, calc(100dvh - 575px))` 里的 `575` 是对"页头+滑块区+导航"的手工求和，任何一个数字变了它就失准。改为交给 flex（`.review-textarea { flex: 1; min-height: 0 }`） | 375 上文本框 284 → ~358px |
| — | 滑块区 150px | **不改**。3 × 44px 触摸目标已触达无障碍下限，压缩会直接提高误触率 | — |

### 3.6 四象限（现状最健康）

实测内容区占用比 86–90%，是四个页面里空间利用最好的。因此**不建议大改**，只做两处：

| 编号 | 改动 | 收益 | 说明 |
| --- | --- | --- | --- |
| Q1 | 页头改悬浮覆盖（`position: absolute` + 半透明 + 模糊），画布上移吃回页头与上边距 | 画布 500 → 549px（+10%） | 页头内容（标题、提示）本身不承载交互，占位属于纯浪费 |
| Q2 | 移动端提示条（"👆 拖动移动 · 长按菜单 · 双击新建"）显示 4 秒后淡出，点击页头可召回 | 同 Q1，去掉常驻占位 | 提示是首次使用才需要的 |

**明确不做的**：不把 `MIN_ZOOM`（`quadrantMath.ts:10`，当前 0.5）调更低来"看见更多"。事件层是整体 `scale(zoom)`，文字随之缩小，0.5 以下文字已经不可读，降低了只是把"看不见"换成"看不清"。缩放已由双指捏合实现，无需新增能力。

### 3.7 弹窗与菜单

`.modal`（移动端已是底部抽屉 + sticky 操作条）、`.context-menu`（移动端已改为底部抽屉 + 48px 行高）实测均已是合理形态。**无需改动**，W1 的抽屉直接复用同一套视觉与手势规则，保持一致。

## 六、需要你确认的三个选择

1. **目标卡的"展开子目标"是否留在卡片上？** 留在外面则卡片有 3 个控件（标题可用宽约 180px），收进菜单则约 260px。我建议**留在外面**——它是长目标的高频入口。
2. **周视图是否要"整周适配"开关（W4）？** 好处是一屏看完 7 天，代价是格子文字退化为色条。你若只在周末扫一眼总量，值得做；若常看具体事件内容，不如保持现状只横滑。
3. **全局瘦身（P2）是否接受标题字号从 23px 降到 19px？** 这是纯视觉取舍，不影响任何交互面积以外的指标。

### 7.2 计划与实测的三处偏差（如实记录）

1. **目标标题可用宽：计划估 221px，实测 129px。** 我按"只留勾选 + 『…』"估算，但按你的决定「展开子目标」保留在卡片上，卡片实际有 3 个控件（勾选 44 + 展开 44 + 「…」44 + 间距），所以 321px 的卡片剩下 129px 给标题。结论仍然成立：竖排消失，单行可读。
2. **复盘文本框：计划估 358px，实测 329px。** 原计划里 R1 假设三个按钮能压到一行，实际在 375px 宽下必须独占一行，页头只从 85px 压到 80px。
3. **R3 那条"硬编码常量 575"是死代码，不是隐患。** 同一断点内更靠后的 `.review-textarea { max-height: none }` 早已覆盖它——判定依据是实测文本框 284px 大于该式在 375 上算出的 96px，说明上限从未生效。已删除以免后人误判，但它本来就没有造成问题。

### 7.3 执行中新发现（计划里没有的）

1. **抽屉展开会遮住 189px 时间轴**：于是把移动端**默认态改为收起**。否则"进来就展开"等于把刚抢回来的 190px 又送掉一半。把手常显条数（`事件预设 · 12`），收起也不会不知道有预设。
2. **`.icon-btn` 的 `display: inline-flex`（theme.css:357）盖掉了 `.goal-more { display: none }`**：两者同为单类选择器，源序在后者胜出。改成 `.goal-card .goal-more` 提权。这与 P0 的 `[hidden]` 是**同一族陷阱**，已在 `AGENTS.md` 记为通用写作规则。
3. **日视图顶栏在 ≤400px 被挤爆**：日期文本不收缩，把「添加」按钮压到换行，工具条 44→48px。已让日期弹性 + 省略号截断、按钮 `flex: none`，工具条回到 44px，时间轴再 +8px。
4. **触屏上预设卡根本改不了/删不掉**：`.preset-actions` 原本只在 `:hover` 显示，而触屏没有 hover。抽屉里已改为一排常驻的两个 44px 按钮。
5. **周视图残留一处待办**：相邻日期列被 sticky 小时轴压住时，事件块首字被裁掉（见 `docs/probes/shots/week-overview-390x844.png` 最左列显示为"程 1"）。按你"周视图不改"的决定本次未动；若要修，思路是给 `.week-grid` 加 `scroll-snap-type: x proximity` + `scroll-padding-left: 52px`，让横滚停在列边界上。
