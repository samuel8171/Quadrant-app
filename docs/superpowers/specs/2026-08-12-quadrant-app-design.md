# 象限 — 大学生计划安排软件设计文档

- 日期：2026-08-12
- 状态：已获用户确认
- 技术栈：Electron + React + TypeScript + Vite
- 打包目标：Windows 便携单文件 exe（portable）

## 1. 目标与范围

做一个面向大学生的时间管理桌面软件，灵感来自《时间管理课程内容总结》。本阶段只实现两个功能模块：

1. **目标**：ToDo List 形式，分长期目标 / 短期目标两栏，长期目标可展开子目标页。
2. **四象限**：可平移缩放的平面直角坐标系，事件卡片可添加、拖动、右键菜单、详细信息。

周计划、周日复盘本阶段只做占位页（显示"该模块开发中"，保留页面骨架）。

预留后期扩展：通过 MCP（stdio）让外部 Agent 可以协作读写计划数据（见第 8 节）。

## 2. 技术架构

- Electron 主进程负责窗口、文件系统与打包；渲染进程使用 React + TypeScript + Vite。
- 数据持久化：单文件 JSON，存放在系统用户数据目录 `%APPDATA%/象限/plan.json`。
- 自动保存：每次数据变更后防抖（500ms）写入；写入采用"临时文件 + 原子替换"，避免写坏数据。
- 打包：electron-builder portable 目标，产出单个 exe（体积约 150~250MB）。
- 测试：核心逻辑（象限边界、缩放钳制、顺序子目标校验、紧急升级）用 Vitest；界面用内置 frontend-testing-debugging 技能做浏览器实测。

## 4. 目标模块

### 4.1 主页面

左右两栏并排：**长期目标**（图标：山峰）与 **短期目标**（图标：日历）。

每条目标是一个圆角卡片（约 8~10px 圆角），包含：

- 左侧勾选框：未勾选为空心方块，勾选后填充蓝色 + 白色对勾；
- 中间标题文字；完成后整行划线置灰；
- 右侧操作：短期目标为编辑/删除；长期目标为"展开"箭头（进入子目标页）+ 编辑/删除。

底部有"＋ 添加长期目标"（蓝色文字按钮）与"＋ 添加短期目标"（绿色文字按钮）。

### 4.2 长期目标详情页（子目标页）

- 顶部："← 返回"、长期目标标题、进度（如 2/5）。
- 子目标列表，每个子目标含勾选框、标题、关系标签（[顺序] / [并列]）。
- 底部"＋ 添加子目标"，添加时可选择关系：顺序 / 并列。

规则：

- "顺序"子目标：必须前一个子目标已勾选才能勾选（程序阻止并提示）。
- "并列"子目标：无依赖，随时可勾选。
- 子目标只存在于长期目标详情页，不显示在短期目标栏。
- 长期目标显示完成进度；全部子目标完成时自动勾选；无子目标时支持手动勾选。

## 5. 四象限模块

### 5.1 坐标系

- 世界坐标系：事件位置用世界坐标（单位：格）存储，与视图平移/缩放无关。
- 1 单位 = 20px（100% 缩放）；缩放范围 0.5x ~ 2.5x。
- 缩放：鼠标滚轮，以鼠标指针位置为中心。
- 平移：Ctrl + 鼠标左键拖拽。
- 原点约束：原点（屏幕坐标）始终距界面四条边 ≥ 10px，平移时自动钳制。

### 5.2 象限色块

- 四个色块是延伸区域（不是固定四等分卡片），随坐标系覆盖整个可见界面；原点移到一角时，对角色块正好铺满剩余界面。
- 色块距两条坐标轴各 10px；靠近原点的一角做小圆角（约 12px）。
- 视觉：半透明深色底 + 象限色霓虹边框，保留概念图的质感。

| 象限 | 含义 | 颜色 |
| --- | --- | --- |
| 第一象限（右上） | 重要紧急 | `#FF8C00` 橙色 |
| 第二象限（左上） | 重要不紧急 | `#FFA500` 黄色 |
| 第三象限（左下） | 不重要不紧急 | `#008B8B` 深青色 |
| 第四象限（右下） | 不重要紧急 | `#483D8B` 深石板蓝 |

### 5.3 象限标签

- 平时不显示。
- 鼠标悬停在某个象限色块内满 1 秒后，该象限名称在对应界面外角淡入：Q1 右上角、Q2 左上角、Q3 左下角、Q4 右下角；鼠标移开即隐藏。
- 文字内容只显示含义，**不带方位词**："重要紧急 / 重要不紧急 / 不重要不紧急 / 不重要紧急"。

### 5.4 事件卡片

```
┌──────────────────────────────┐
│ ○ 明天交高数作业          │
│ 截止：08-14 23:59           │
└──────────────────────────────┘
```

- 双击象限内任意一点：在该点生成输入框，回车保存、Esc 取消；空内容丢弃；新事件自动归属所在象限。
- 事件框宽度由文本自动决定，最大 20 单位（400px @100%），超宽换行；高度随行数增长。
- 事件与坐标系保持相对位置不变、相对大小不变（随缩放等比变化）。
- 平时不显示左侧小圆点；鼠标悬停事件框时，左侧出现空心小圆点（同象限色），抓住可拖动事件。
- 事件框整体必须落在色块范围内（距轴 10px 边界以内），不允许跨轴/压线；拖入另一象限即切换归属并自动对齐到新象限。

### 5.5 右键菜单

事件卡片右键菜单：剪切、复制、粘贴、删除、保存、详细信息。

- 剪切：复制到内部剪贴板并删除原卡片。
- 复制：复制到内部剪贴板。
- 粘贴：在剪贴板事件同象限的偏移位置生成新卡片（若跨象限约束失败则就近放置）。
- 删除：删除事件（需确认）。
- 保存：立即写盘（平时已有自动保存，此操作提供手动入口）。
- 详细信息：打开详情对话框。

### 5.6 详细信息对话框

- 修改所属象限（四选一）；修改后事件自动对齐到新象限色块内。
- 备注（多行文本）。
- 截止时间（可选，datetime-local）。
- 紧急升级时间（可选，仅 Q2/Q3 事件显示）：到点后自动执行升级：
  - Q2 → Q1（重要不紧急 → 重要紧急）
  - Q3 → Q4（不重要不紧急 → 不重要紧急）
  - 只水平移动：保持世界 y 不变，沿纵轴镜像到相邻象限。
- 事件超过截止时间后显示逾期样式（红色边框/文字标记）。

## 6. 数据模型

```ts
type Quadrant = 1 | 2 | 3 | 4;

interface QuadrantEvent {
  id: string;
  text: string;
  remark: string;
  quadrant: Quadrant;
  x: number;          // 世界坐标（单位：格），卡片左上角
  y: number;
  width: number;      // 单位：格，<= 20
  deadline?: string;  // ISO 时间
  escalateAt?: string; // 仅 Q2/Q3 可设
  createdAt: string;
}

interface Subtask {
  id: string;
  title: string;
  done: boolean;
  relation: 'sequential' | 'parallel'; // 相对前一个子目标
  order: number;
}

interface Goal {
  id: string;
  title: string;
  type: 'long' | 'short';
  done: boolean;
  subtasks: Subtask[]; // 仅长期目标使用
  order: number;
  createdAt: string;
}

interface AppData {
  version: 1;
  goals: Goal[];
  events: QuadrantEvent[];
}
```

## 7. 数据持久化与错误处理

- 文件：`%APPDATA%/象限/plan.json`；每次写入前保留 `plan.backup.json`。
- 写入流程：先写临时文件，成功后原子替换正式文件；失败时提示用户并保留内存数据。
- 启动时读取：文件不存在则创建默认空数据；文件损坏则尝试读取备份，仍失败则提示并从空数据启动（不静默覆盖原文件）。

## 8. MCP 协作预留（后期实现）

为让外部 Agent 能与"象限"协作，本阶段做架构预留：

- 数据访问独立成层（renderer 通过 preload 暴露给主进程的 data-access 模块调用），MCP 服务与 UI 共用同一数据层，避免两套读写逻辑。
- 预留 MCP stdio 服务骨架（`mcp/` 目录）：工具清单先定义完整，默认不随主程序启动，后期补实现与文档。
- 计划工具清单：
  - `list_goals` / `get_goal` / `create_goal` / `update_goal` / `toggle_goal` / `delete_goal`
  - `list_events` / `create_event` / `update_event` / `delete_event`
  - `list_subtasks` / `add_subtask` / `toggle_subtask`
